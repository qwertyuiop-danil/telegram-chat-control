# Telegram: чаты и сообщения

## Первый запуск

Скилл рассчитан на macOS и хранит Telegram-сессию в Keychain, а локальный индекс — в `~/.codex/telegram-chat-control/`. Эти данные не входят в папку скилла и не должны попадать в GitHub.

1. Создать API ID и API hash приложения Telegram на [my.telegram.org](https://my.telegram.org). Не публиковать API hash.
2. Открыть приложение «Связка ключей» и создать две записи типа «Пароль» для текущего пользователя macOS:
   - сервис `codex-tg-reader-api-id` — значение API ID;
   - сервис `codex-tg-reader-api-hash` — значение API hash.
3. Запустить подключение аккаунта из папки скилла:

   ```bash
   cd /path/to/telegram-chat-control
   uv run scripts/telegram.py login-qr
   ```

4. Отсканировать показанный QR-код в Telegram: **Настройки → Устройства → Подключить устройство**. Если включён облачный пароль, ввести его только в защищённом системном окне.
5. После подключения проверить аккаунт и локальный индекс:

   ```bash
   uv run scripts/telegram.py account list
   uv run scripts/telegram.py sync
   uv run scripts/telegram.py list --filter personal --limit 10
   ```

При первом запуске `sync` загружает историю в локальную SQLite-базу; это может занять время. Не копировать в репозиторий папки `~/.codex/telegram-chat-control/`, файлы `*.sqlite3`, Telegram-сессии, QR-коды, выгрузки чатов или медиа.

## Как это работает

Запускать команды из папки скилла:

```bash
cd /path/to/telegram-chat-control
uv run scripts/telegram.py <команда>
```

Использовать `list`, `read`, `search` и `comment` без обращения к Telegram: они читают локальную SQLite-базу и выполняются быстро. Базу обновляет уже запущенный фоновый процесс примерно раз в минуту. Не запускать дополнительный `watch` или `sync` для обычного чтения.

У каждого подключённого аккаунта свой индекс в `~/.codex/telegram-chat-control/data/accounts/`; он доступен только владельцу (`0600`). Никогда не выводить данные Keychain, Telegram-сессию, API hash и пароль двухэтапной проверки.

## Аккаунты

Обычные команды всегда работают с активным аккаунтом. Существующая одиночная сессия и история при первом запуске автоматически переносятся в мультиаккаунтный формат.

Добавить аккаунт: команда откроет QR-код как изображение. После сканирования она при необходимости спросит облачный пароль защищённым системным окном, затем попросит комментарий и сделает аккаунт активным.

```bash
uv run scripts/telegram.py login-qr
```

Управление подключениями:

```bash
uv run scripts/telegram.py account list
uv run scripts/telegram.py account use --id ID_АККАУНТА
uv run scripts/telegram.py account comment --id ID_АККАУНТА --text "Основной аккаунт"
uv run scripts/telegram.py account disconnect --id ID_АККАУНТА
```

`disconnect` удаляет только сессию подключения; локальная история этого аккаунта остаётся на диске. Фоновый процесс синхронизирует только активный аккаунт.

## Найти чат

Получить 30 последних чатов, в которых владелец сам отправлял сообщения:

```bash
uv run scripts/telegram.py list --filter personal --limit 30
```

Здесь `personal` означает не «только личные диалоги», а «чаты с участием владельца». В результат могут входить личные чаты, боты, группы и каналы.

Другие фильтры:

- `all` — все проиндексированные чаты;
- `groups` — группы;
- `channels` — каналы;
- `private-channels` — каналы без публичного username.

Добавлять `--query ТЕКСТ`, чтобы искать по названию, username или личному комментарию. Брать `peer_id` из результата и использовать его в следующих командах.

## Прочитать или найти сообщения

Прочитать последние 50 сообщений, начиная с самых новых:

```bash
uv run scripts/telegram.py read --peer ID_ЧАТА
```

По умолчанию выводить удобные строки `время | отправитель | текст`. Добавлять `--json`, когда нужны ID сообщений, reply, тип медиа или другие структурированные поля.

Ограничивать выборку при необходимости:

```bash
uv run scripts/telegram.py read --peer ID_ЧАТА --limit 100
uv run scripts/telegram.py read --peer ID_ЧАТА --after 2026-08-01 --before 2026-08-15
uv run scripts/telegram.py read --peer ID_ЧАТА --min-id 100 --max-id 200 --json
```

Искать сообщения локально по всем чатам или внутри одного чата:

```bash
uv run scripts/telegram.py search "текст запроса" --limit 50
uv run scripts/telegram.py search "текст запроса" --peer ID_ЧАТА
```

Поиск требует совпадения всех значимых слов запроса.

## Заметки, профили и медиа

Сохранить личную пометку к чату:

```bash
uv run scripts/telegram.py comment --peer ID_ЧАТА --text "Рабочий чат"
```

Получить профиль пользователя или сведения о канале:

```bash
uv run scripts/telegram.py info --peer @username
uv run scripts/telegram.py info --peer ID_ЧАТА --refresh --download-photo
```

Использовать кэш профиля до 24 часов; добавлять `--refresh` только когда нужны свежие данные.

Расшифровать голосовое или скачать фото сообщения:

```bash
uv run scripts/telegram.py transcribe --peer ID_ЧАТА --message ID_СООБЩЕНИЯ
uv run scripts/telegram.py photo --peer ID_ЧАТА --message ID_СООБЩЕНИЯ
```

Добавлять `--open` к `photo` только по просьбе пользователя. Расшифровка и сведения о подарках могут быть недоступны из-за ограничений Telegram API; в таком случае кратко сообщать причину.

## Отправить сообщение

Отправлять только в чат из allowlist. Перед отправкой показывать получателя и точный текст, если пользователь ещё не дал прямую команду отправить именно этот текст именно этому получателю.

Проверить разрешённых получателей:

```bash
uv run scripts/telegram.py allowed
```

Добавлять или удалять разрешение только по прямому указанию владельца:

```bash
uv run scripts/telegram.py allow --peer ID_ЧАТА --comment "Можно писать"
uv run scripts/telegram.py disallow --peer ID_ЧАТА
```

Отправить сообщение:

```bash
uv run scripts/telegram.py send --peer ID_ЧАТА --text "Точный текст"
```

Не обходить проверку владельца аккаунта и allowlist. Если отправка заблокирована, объяснить, какое разрешение отсутствует; не выполнять `allow` автоматически.
